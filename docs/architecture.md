# 架构说明

## 1. 要解决的问题

云服务器需要读写对象存储，但出于合规或安全要求，这台机器**不允许有任何公网出口**：
不绑弹性公网 IP、不挂 NAT 网关、路由表里没有任何指向公网的条目。

对象存储是区域级服务，它的访问入口是一个域名。默认情况下解析出来的是公网地址
在没有公网出口的子网里必然不通。VPC 终端节点就是用来解决这件事的：
把访问路径收在云内网里，让报文不出 VPC 就能抵达对象存储。

本实践给出两条路径，并把它们的差别摊开讲清楚。

## 2. 整体拓扑

```

┌──────────────────────────────────────────────────────────────────┐

│ └─────────┬──────────┘ │ │
```

注意转发节点自己访问对象存储时，走的也是**路径一**。
路径二并不是绕开网关型终端节点，而是在它前面多加了一跳可被跨 VPC 消费的入口。

## 3. 两条路径的差别

| | 路径一 · 网关型终端节点 | 路径二 · 接口型终端节点 |
|---|---|---|
| 实现机制 | 云平台往路由表注入一条指向对象存储的路由 | 在子网里落一张网卡，分配固定内网地址 |
| 客户端要做什么 | 什么都不用做，路由生效即可 | 把对象存储域名的解析指向终端节点地址 |
| 谁能用 | **只有本 VPC 内的资源** | 可跨 VPC、跨账号；可经云专线 / VPN 从本地机房访问 |
| 访问控制 | 终端节点策略（限制能做哪些操作） | 白名单（限制哪些地址能连） + 安全组 |

**选型建议：** 只要访问方都在同一个 VPC 内，用路径一。
只有当需要跨 VPC、跨账号，或者要让本地机房经专线访问对象存储时，才需要路径二。

## 4. 路径一的关键点

### 4.1 不需要自定义路由表

VPC 的默认路由表本身只有 local 路由，子网默认就是私有的。
创建网关型终端节点时不指定 `routetables`，云平台会把路由注入默认路由表。

代码里刻意不创建自定义路由表 —— 自定义路由表受配额限制、开通需要提交工单
而它在这个场景下没有带来任何默认路由表给不了的东西。

### 4.2 终端节点策略

网关型终端节点支持挂策略，限制经由它能做什么。本实践只放通读取：

```hcl
policy_statement = jsonencode([{
Effect = "Allow"
Action = ["obs:bucket:ListBucket", "obs:bucket:GetBucketLocation", "obs:object:GetObject"]
Resource = ["obs:*:*:bucket:<bucket>", "obs:*:*:object:<bucket>/*"]
}])
```

这条策略与委托的权限是**取交集**的关系：委托给了读写权限
但经由这个终端节点访问时，写操作会被终端节点策略拦下。
可以用它来验证策略确实生效。

### 4.3 子网 DNS 必须保持内置解析

子网的 `dns_list` 留空即使用云内置 DNS。
把对象存储域名解析到**内网地址**是内置 DNS 的能力
改成公共 DNS 会解析到公网地址，在无出口的子网里直接不通。

## 5. 路径二的关键点

### 5.1 为什么需要一个转发节点

云平台预置的公共终端节点服务里，对象存储只提供**网关型**
没有接口型。要拿到「固定内网地址 + 可跨 VPC 消费」这种形态
需要自己把一台云服务器发布成接口型终端节点服务。

转发节点做的事很简单：把 443 端口收到的 TCP 连接原样转到对象存储的内网地址。

### 5.2 四层转发，不解 TLS

转发节点用操作系统自带的 netfilter 做 DNAT + SNAT，不碰 TLS 内容。
客户端携带的 SNI 与 Host 原样送达对象存储，证书由对象存储自己出示
**转发节点上不需要放任何证书**。

这也决定了客户端必须继续使用对象存储的原始域名，只改解析结果。
因此终端节点的 `enable_dns` 设为 `false`：
云侧生成的 `*.vpcep.myhuaweicloud.com` 默认域名不在对象存储的证书覆盖范围内
用它访问会证书校验失败。

### 5.3 不装任何软件

子网没有公网出口，装不了软件包。转发能力完全由内核提供，零外部依赖。
这一点反过来也是对「确实没有公网出口」的验证 ——
如果初始化过程需要联网装包并且成功了，说明私有前提已经被破坏了。

### 5.4 两个必须记住的网络细节

**转发节点网卡必须关闭源/目的检查。**

```hcl
network {
source_dest_check = false
}
```

这台机器要转发目的地址不是自己的报文。开着源/目的检查会在网卡层面丢包
**没有任何日志**，现象只是连接超时，排查成本极高。

**转发节点安全组必须放通 `198.19.128.0/17`。**

终端节点把客户端报文转发到后端时，源地址会被改写成这个网段。
只放通 VPC 网段同样表现为静默超时。

顺带一条：**VPC 网段不得与 `198.19.128.0/17` 重叠**，那是终端节点的内部转发网段。

## 6. 权限设计

客户端云服务器**不携带任何长期密钥**。它绑定一个委托
通过实例元数据接口拿到临时凭据，凭据在有效期内自动轮换。

对象存储是**全局服务**，权限必须授在 domain 级：

```hcl
domain_roles = ["OBS OperateAccess"]
```

授在 `project_role` 里不会报错，但运行期取到的临时凭据不含对象存储权限
表现为 403，是一个很容易走弯路的坑。

## 7. 远程接入

客户端和转发节点都没有公网地址，也没有跳板机。
登录方式是**弹性云服务器控制台的「远程登录（VNC）」**。

它走的是管理面通道，不经过 VPC 网络，因此不需要为「能登进去」这件事
创建任何终端节点、安全组规则或跳板机。
这是本实践能做到零公网出口的关键前提之一。

## 8. 适用边界

本实践为演示而简化，下列差距在生产使用前需要补齐：

| 项 | 本实践 | 生产建议 |
|---|---|---|
| 转发节点可用性 | 单台云服务器 | 多台 + 共享型负载均衡器作终端节点服务后端（`server_type = LB`） |
| 转发目标地址收敛 | 定时器 5 分钟重解析一次 | 缩短周期，或改用支持域名后端的代理 |
| 转发节点监控 | 无 | 接入云监控，对端口存活与转发规则告警 |
| 桶策略 | 仅私有 ACL | 叠加桶策略，限制只允许来自指定终端节点的请求 |
| 密码登录 | 初始密码由变量注入 | 改用密钥对，禁用密码登录 |

路径二本身也不是唯一选择。如果访问方都在同一个 VPC 内
**不要**为了「看起来更完整」而部署路径二 —— 直接把 `enable_interface_path`
置为 `false` 即可。
